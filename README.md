# متجري — إدارة السوبر ماركت

واجهة عربية للموبايل: المنتجات والباركود، فواتير البيع والشراء، سندات القبض والدفع والمصروفات، تقرير الأرباح، كشف حساب الموردين والزبائن، ورصيد الصندوق بالليرة السورية.

الخانات الرقمية تبدأ فارغة. يحوّل التطبيق الأرقام العربية إلى الإنجليزية تلقائياً، ويحافظ على الأصفار داخل الباركود والأرصدة الفعلية.

## حالة التشغيل

ملفات الواجهة في جذر المستودع، وملفات الربط في `apps-script/`. يلزم نشر Apps Script وربط عنوانه لتخزين العمليات في Google Sheets. وضع التجربة يحفظ بياناته في المتصفح فقط.

## تفعيل الربط

1. افتح ملف البيانات الخاص في Google Sheets ثم **Extensions → Apps Script**.
2. انسخ `apps-script/Code.gs` إلى ملف Code، وأنشئ Script باسم Engine من `apps-script/Engine.gs`، وHTML باسم Bridge من `apps-script/Bridge.html`.
3. أظهر ملف manifest من Project Settings واستبدله بمحتويات `apps-script/appsscript.json`.
4. احفظ وشغّل `onOpen` لتفويض المشروع ثم أعد تحميل الشيت.
5. **السوبر ماركت → تهيئة وربط التطبيق**: الشيت وأصل الموقع معدّان مسبقاً. يحافظ التحديث على اسم المستخدم وكلمة المرور المحفوظين. عند غياب تهيئة سابقة فقط يطلب كلمة مرور لا تقل عن 16 حرفاً ويكون اسم المستخدم `admin`.
6. حدّث النشر القائم من **Deploy → Manage deployments → Edit → New version → Deploy** مع الإبقاء على رابط النشر الحالي. إعداد النشر المطلوب: التنفيذ باسمك **Me** والوصول **Anyone**. يبقى الشيت خاصاً؛ البيانات محمية بتسجيل الدخول في التطبيق.
7. `config.js` يتضمن بالفعل رابط النشر الموجود في المستودع؛ لا يلزم تعديل أي رابط عند تحديث نفس النشر. شاشة الدخول تعرض اسم المستخدم وكلمة المرور فقط.
8. فعّل GitHub Pages من **Settings → Pages → Deploy from a branch → main → /(root)** وافتح الرابط الذي يعرضه GitHub.

لا تضع كلمة المرور أو سجلات المحاسبة أو النسخ الاحتياطية في المستودع العام. لا تبدأ العمليات الفعلية قبل ظهور **متصل بجوجل شيت** واختبار الحفظ.

## تحديث الأرباح والمصروفات والدخول

- شاشة الدخول تحتوي اسم المستخدم وكلمة المرور فقط؛ إعداد الخادم في `config.js`.
- بعد تحديث خادم قائم، اسم المستخدم الافتراضي `admin` مع كلمة المرور الحالية. يمكن تغييره من قائمة **السوبر ماركت → تغيير اسم المستخدم** بعد تشغيل `onOpen` وإعادة تحميل الشيت.
- حدّث `Code.gs` و`Engine.gs` في مشروع Apps Script القائم. اختر **Deploy → Manage deployments → Edit → New version → Deploy** للحفاظ على رابط النشر. تحديث GitHub وحده لا يحدّث خادم Google.
- لا تُعد التهيئة إذا كانت إعدادات الاتصال وكلمة المرور تعمل؛ تبقى محفوظة. إذا لم يكتمل الإعداد سابقاً، أكمل التهيئة من قائمة الشيت.
- سند المصروفات يتطلب مبلغاً وتصنيفاً وبياناً. يؤثر على الصندوق وصافي الربح، دون تسوية ذمم الموردين والزبائن. يدعم الطباعة والإلغاء بقيد عكسي.
- التقرير بفترة مع طباعة/PDF وCSV: صافي المبيعات، تكلفة المبيعات، مجمل الربح، المصروفات، صافي الربح.
- التكلفة بمتوسط المخزون المتحرك حسب **ترتيب التسجيل**. قيمة المخزون الافتتاحي = الكمية × التكلفة عند إنشاء المنتج. المشتريات تزيد القيمة بعد توزيع الخصم؛ البيع يحفظ تكلفته وقت الاعتماد. تعديل سعر المنتج لاحقاً لا يغيّر أرباح الفواتير السابقة.
- الفواتير القديمة يعاد حساب تكلفتها من سجل الأحداث التاريخي. دقة الأرباح تعتمد على صحة تكاليف الافتتاح والمشتريات. التقريب إلى أقرب ليرة مع تسوية كلفة آخر كمية متبقية.
- البيع الآجل يدخل في الأرباح عند البيع، ولا يُحسب قبض الدين مرة ثانية. دفعات الموردين وشراء مخزون غير مباع لا تُسجّل مصروفاً تشغيلياً.
- الإلغاء يعكس الربح في تاريخ قيد الإلغاء، ولا يمحو نتائج الفترات السابقة. لا يمكن إلغاء حركة بتاريخ يسبق أصلها.
- سندات الدفع العامة القديمة لا تُحوّل تلقائياً إلى مصروفات. راجعها قبل الاعتماد على صافي الربح؛ لا تسجلها مرة أخرى دون عكس الحركة الأصلية حتى لا تخصم النقد مرتين.
- ينشئ الخادم جداول **المصروفات** و**الأرباح** و**ملخص الأرباح** عند تحديث العرض أو حفظ حركة. لا يعدّل سجل الأحداث القديم.

## التحقق والحدود

اجتاز المحرك 25 اختباراً محاسبياً و14 اختباراً للأرباح والمصروفات، مع تحقق الخادم من اسم المستخدم وكلمة المرور وإعادة المحاولة، واختُبر الإدخال الرقمي واحتساب الإجماليات في المتصفح. يلزم اختبار الاتصال الحي وكاميرا الهاتف بعد إتمام النشر. تشمل النسخة تقرير أرباح؛ لا تشمل الضرائب أو الإهلاك أو صلاحيات الموظفين المتعددة أو المرتجعات الجزئية.

## تحديث 2026-10-20

- إعداد رابط الشيت وأصل الموقع تلقائياً، والحفاظ على بيانات الدخول القائمة عند التهيئة.
- معالجة اختلاف قراءة UPC-A من 12 رقماً وEAN-13 المكافئ ذي الصفر الأول؛ تبقى أرقام المنتجات الأصلية محفوظة كما أدخلت.
- اختبار مكتبة القراءة الفعلية على بيانات صور باركود مولّدة: EAN-13 (مثالان)، EAN-8 وUPC-A. نجحت الأمثلة الأربعة. اختبارات حفظ الأصفار وتحويل الأرقام العربية ومطابقة UPC/EAN نجحت أيضاً.
- اختبار المصوّرة الفعلية على هاتف المستخدم والتحقق من تسجيل الدخول والحفظ على الخادم غير منفّذَين في هذا التحديث. نجاح فك الصور لا يضمن إذن الكاميرا أو وضوح التصوير على كل هاتف.
- جرى تجهيز تبويبات المصروفات والأرباح وملخص الأرباح في الشيت. وجودها لا يعني اكتمال نشر خادم Apps Script.
- اختبارات التهيئة بمحاكاة خدمات Google نجحت لحفظ كلمة المرور الحالية، والتهيئة الأولى، والإلغاء دون كتابة، ومنع الربط العرضي بشيت مختلف.

جميع ملفات المشروع متاحة من زر **Code → Download ZIP** في المستودع.
